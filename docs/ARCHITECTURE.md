# 项目架构

本文给出重构后 BridgeZoo 的目录结构、模块职责与数据流。总体研究设计见
[DESIGN_MAPPO.md](DESIGN_MAPPO.md)，开发进度见仓库根的 [TODO.md](../TODO.md)。

## 设计原则

1. **几何唯一真源**：所有几何/截面参数集中在 `bridgezoo/envs/geometry.py`，FEM、施工
   阶段、渲染均从此取数，杜绝历史代码中多处重复且不一致的几何公式。
2. **求解器分层**：RL 内核用自写**线性变刚度前进分析**求解器（快）；OpenSees 仅作
   **离线校核**（准）。二者解耦，互不进入对方主线。
3. **CTDE 边界清晰**：环境同时暴露"局部观测"（分散执行）与"全局状态"（集中训练），
   actor 只看局部、critic 只看全局。
4. **骨架先行**：先把接口、说明、测试位、里程碑钉死，再按 `TODO.md` 逐层实现，
   保证任意时刻仓库可 import、测试可运行（未实现项 skip）。

## 数据流（一个 episode）

```
reset()
  └─ staged_builder.build_stages(geometry)  → [Stage0, Stage1, ...]
  └─ StagedFrameModel 初始化（阶段0：塔+0#段自重）

step(actions)  // 每次推进一个施工阶段
  ┌─ 取当前阶段 active_cable
  ├─ CableAgent.apply_erection / apply_adjustment(动作)   // 改股数→改K / 改张拉→改荷载
  ├─ StagedFrameModel.activate(本阶段单元)               // 重装配 K_k（变刚度）
  ├─ apply_incremental_load + apply_cable_pretension      // 组装 ΔF_k
  ├─ solve_increment() → 累加位移 u                       // 线性增量
  ├─ accumulate() → 梁挠度 + 各索轴力 → CableAgent.update
  ├─ 组装 obs_i（局部）/ state（全局）/ 共享奖励（终局+势能塑形）
  └─ 推进阶段游标；成桥→terminated，超步→truncated

训练（MAPPO, CTDE）
  Actor(obs_i, mask) → 动作        // 分散执行
  CentralCritic(state) → V          // 集中训练
  RolloutBuffer + GAE → PPO 更新
```

## 编号约定（务必一致）

成桥/施工两套模型各自固定梁/塔节点与梁/索单元的 id 约定（`staged.builder` 为施工模型真源，
`completed/` 经 `staged.completed` 由同一施工计划派生），同模式内两后端必须共用同一套编号，否则无法交叉校核。

`single_staged/` 源码与内部导入完全独立，采用独塔左悬臂拓扑：右梁只有一个全固定端节点，
每根右索连接独立的全固定地锚；`tip_free` 安装并求解左侧自由端，随后最终
`left_tip_uy_lock` 阶段把节点 201 的竖向位移锁定在当前位置，之后 `left_span` 阶段按
YAML 同名长度向左切线激活辅助跨并把新端节点 202 的竖向位移锁定在诞生位置；当
`dw != 0` 时，最终 `phase2` 阶段对全部主梁单元施加二期均布荷载。
分析和优化统一使用 `scripts.staged_analysis` 与
`scripts.optimize_cables` 入口。桥梁 YAML 的 `bridge_type` 负责模型分派：`normal` 使用
`staged`，`single` 使用 `single_staged`；通用优化算法内部对应
`CableOptimizationProblem.model_family`。

## `single_staged` 3D 详细施工架构

3D 模型采用后缀明确的新 API（如 `build_single_staged_3d`、
`SingleStagedDirectSolver3D`），旧 2D 接口在迁移期间保持不变。坐标约定为
`x` 纵桥向、`y` 横桥向、`z` 竖向，每个节点有
`(ux, uy, uz, rx, ry, rz)` 六个自由度。

- `envs.geometry.SingleTowerGeometry3D` 是纵横向尺寸及 H/箱形截面尺寸的唯一真源，
  继承旧单塔模型的 `n_seg`、`anchor_*`、`left/right_*`、`right_fix`、`left_span`
  语义。
- `single_staged.sections3d` 从真实截面尺寸推导 `A/Iy/Iz/J`；默认主梁、横梁为钢制
  H 型截面，塔身为 C50 混凝土空心箱形截面，桥面板为 C50 混凝土等效矩形板条。
- `single_staged.model3d` 定义与后端无关的空间梁、索、支座、全局均布荷载、刚臂、
  阶段激活和统一结果 IR。
- 两根主梁沿横桥向对称布置，横梁使用独立的等间距网格并与主梁共节点；索锚点可额外
  细分主梁但不会破坏横梁等间距。桥面板纵横梁格位于主梁轴线上方的独立参考面，通过
  6 自由度刚臂表达偏心。当桥面宽度大于主梁间距时，板梁格在两根主梁外侧各增加一排
  边缘节点，横向板条显式形成两侧悬臂；纵向板条按实际影响宽度分配。纵横板条都参与
  刚度。桥面板湿重不直接加载到新生板条，而是在组合前等效到当次新架设的两根钢主梁。
- 单塔位于桥轴线，双索面分别连接两根主梁。每个几何架设阶段细分为三步：
  `steel_and_A` 激活钢梁和一对主跨索/背索并施加预拉力 A；`deck_weight_and_B` 将湿桥面板
  自重换算成两根新钢主梁上的线荷载并施加预拉力 B；`composite` 删除临时荷载定义、
  零应力激活偏心桥面板梁格和刚臂，使其与钢梁共享自由度形成组合体系。无拉索的悬臂端
  和辅助跨仍保留相同三步节奏。`pretension_a_ratio` 显式控制总预拉力在 A/B 间的分配。
- 梁格、桥面板及可选辅助跨全部激活后，若配置了二期荷载则追加独立的
  `secondary_load` 最终阶段。`secondary_main_girder_line_load` 作为每根主梁的全局竖向
  线荷载施加到两条钢主梁，`secondary_deck_pressure` 按实际影响宽度转换为各条桥面纵向
  板条的线荷载；前者用于护栏等沿桥设施，后者用于沥青铺装等面荷载。
- `direct3d` 为自研线弹性 Euler-Bernoulli 空间梁 + 线性杆增量求解器，保存节点提交位移、
  构件出生位移、既有内力和支座反力，刚臂通过精确自由度凝聚实现。新钢结构组在正式A步
  求解前先进行一次零荷载虚拟刚度求解：既有接口节点取上一阶段提交位移，新节点通过本步
  实际空间梁和拉索刚度进行柔性切线延拓；该虚拟内力随后丢弃，所得构形作为新构件无应力
  出生参考。没有新增约束的自由悬臂自然退化为刚体切线外推；
  `SingleStagedDirectBatchSolver3D` 在每个施工细步只组装、凝聚并分解一次当前刚度矩阵，
  将全部预张力扰动组成多右端矩阵一次回代。`opensees3d` 从同一 IR 为每个增量重建当前
  `elasticBeamColumn`、`Truss` 和 `rigidLink beam` 切线模型，并在 Python 状态中累计提交量，
  因而与自研后端逐细步交叉校核。

当前阶段语义是真正的路径相关线性增量施工，包含零应力构件诞生和安装构形/支座位移锁定；
仍不包含索垂度、拉索仅受拉或几何非线性。`scripts/bridges/omo_bridge_3d.yaml` 是完整的 OMO
3D 物理输入，计算入口为 `python -m scripts.single_staged_3d --bridge omo3d`。

`render.staged3d` 消费同一份 `SingleStagedPlan3D/StagedResult3D`，因此自研和 OpenSees
后端共享渲染语义。它仿照 2D 逐阶段输出：未变形参考网格、位移放大后的空间梁格与箱塔
轴线、半透明桥面板、双索面、刚臂、支座和新增构件高亮，并可同时保存阶段 PNG 与 GIF。
独立的 `--dxf` 开关通过 `ezdxf` 输出最终状态的 3D DXF，可与任意 `--render` 模式组合；
节点、主梁、横梁、板条、塔、拉索、刚臂和桥面板分别置于命名图层。DXF 坐标采用模型
真实未变形坐标，单位为米，不使用绘图位移放大比例，便于 CAD 内直接检查几何尺寸。
未启用 `--dxf` 时图像渲染不会附带生成 DXF；所有渲染和导出都只做后处理，不进入求解器
或改变任何力学结果。

3D 索优化使用独立入口 `scripts.optimize_cables_3d`、评估适配层
`optim.single_staged3d.CableDesignEvaluator3D` 和专用内核
`optim.staged3d_optimizer.StagedCableOptimizer3D`，不复用 2D 仿射/混合搜索算法。设计向量
按施工阶段排列为 `(背索组, 主跨索组)`，每个组同步控制横桥向两根实体索，并包含三类
变量：单根实体索的整数股数、总张拉力 T、A/(A+B) 张拉力系数。

算法按工程职责分为三层。第一层把初步张拉直接表示为 `T_A`，并在全部 `T_B=0` 的初步
平衡工况中依施工顺序处理每一阶段。当前阶段执行零张拉基准、back 索探针、主跨索探针
三个部分施工分析，形成从两组 `T_A` 到“塔端 ux、梁端平均 uz”的 2×2 影响矩阵；一次
有界线性最小二乘即可得到平衡力，再用第四个工况校核。矩阵秩、条件数、上下界激活状态
和实际残差共同给出该阶段是否有稳定可行解，不再对 A 系数做数值差分优化。

第二层固定 `T_A`，用低维光滑曲线描述 `T_B`。默认对 back 索和主跨索分别设置4个
Bernstein 控制点，三次非负分片权重将8个归一化控制量插值成完整 `2*n_seg` 组 B 张拉力；
控制量位于 `[0,1]` 时插值结果自然满足每组剩余张拉上界。一个 B=0 基准工况和8个曲线
方向探针建立成桥两根主梁 `uz`、塔顶/塔锚 `ux` 和各组索应力响应矩阵。有界最小二乘的
全部迭代只做矩阵乘法，完成后增加一个真实 OpenSees 工况，验证插值后的完整设计。
因此默认固定股数预算为 `4*n_seg+10` 次 FEM，且只有10个 B 工况运行完整施工序列。
`piecewise-linear` 提供局部性更强的备选曲线；`auto` 共享基准并比较两种曲线的实际验证
目标值，4控制点时 B 预算为19个完整工况。若未来改为几何非线性，
建议保留这一接口并升级为信赖域序列响应面：验证失败时在当前 B 点重新线性化，而不是退回
每个数值差分点都跑完整 FEM。

股数不是逐索自由搜索。输入或候选股数先分别拟合 back/主跨的同族低维曲线，再对控制值
作非递减投影，最后插值、取整并强制由内向外不减少。这既编码了外侧索通常更粗的工程先验，
也保证最终仍得到完整 `2*n_seg` 组整数股数；每组 T、A/B 系数和实体索映射继续写入结果。

B 的最终验证工况与普通完整求解成本相同，但保留全部阶段记录。因此输出同时包含两套 A
残差：一套是直接求解时“全部 B=0”的初步平衡残差，另一套是优化后实际 B 施工序列下的
A 子阶段残差。后者用于量化解耦误差，不额外增加 FEM 工况。若误差不可接受，可显式设置
`--ab-correction-passes 1`：固定上一轮 B 序列重算各阶段 A，再重建并优化 B 响应面；每个
校正轮次重复一套当前低维曲线工况。若校正后仍不满足，输出会指向张拉上界、股数或 B
目标之间的可行性冲突，而不是继续盲目增加迭代。

最外层股数搜索会改变索面积和响应矩阵，因此每个候选必须重建上述两层。默认不自动执行；
连续 A/B 设计稳定后可显式增加 `--strand-iterations`，每轮只评估一个应力引导候选。当前
优化后端只实现 OpenSees；自研 3D 后端仍可用于普通分析和交叉验证，但不进入新版优化流程。

v3 `best_design.json` 保存组到实体索单元 ID 的映射、股数、T、A/B 系数、A/B 分力、
A 影响矩阵可行性、B 响应面校核误差、FEM 工况耗时和成桥结果，支持同协议断点续跑。
`scripts.single_staged_3d --design` 会校验
T、系数和 A/B 分力的一致性后把三类变量写回同一物理配置，因此可用现有 3D 逐阶段计算
直接复现；旧 v1 设计保持只读兼容。

### 独立工程循环调索

以下四项作为3D施工调索优化的项目级理想目标和后续验收准则：

1. 新梁段以零应力状态激活；施加本组拉索 A 张拉力后，新激活梁段相对切线诞生位置的
   变形基本为零，同时索塔锚固节点的水平变形基本为零。
2. 除初始索力 A 的激活校核外，不以任何中间施工阶段作为调索目标；拉索 B、主梁位移和
   桥塔位移统一以最终 `secondary_load` 状态为依据，主梁竖向位移和塔锚水平位移均控制为零。
3. 各拉索最终 `secondary_load` 应力原则上处于400～600 MPa，中心目标为500 MPa；成桥状态应保持
   合理材料利用率，低应力并非更优解。
4. 二期恒载施加后的主梁目标直接定义为水平（控制位移为0），不使用300 mm常数目标或
   其他预拱度曲线。

当前工程循环已经按上述口径实现：A 使用激活阶段切线零位移，B 与根数轮使用最终状态响应。
在工程循环的决策优先级中，第3项的最终应力调整最高：根数变化只要使500 MPa指标
改善即可接受，允许暂时扰动位移；同一循环末尾的线形修复轮以及后续索力轮必须在新根数和
新刚度下重新寻找位移平衡位置。

`scripts.optimize_cables_3d_engineering` 与低维全局优化器并列，内核为
`optim.engineering_cycle3d.EngineeringCableCycleOptimizer3D`，不调用或覆盖前者。它不建立
局部或全局影响矩阵。每个循环先完整回放当前 A/B 与股数方案。只有 A 从本组激活记录读取
响应：梁端 `z` 以本组钢梁切线诞生位置为零点，塔锚 `x` 使用该激活状态的实际位移。每个组
的 B 梁端 `z`、B 塔锚 `x` 和索应力都从同一个最终 `secondary_load` 记录读取。第一轮固定
根数只调整 A/B 索力：A 追踪激活零位移，B 追踪最终主梁和塔锚零位移。最终主梁目标是硬编码
的0，不存在阶段预拱度目标，也不作相邻阶段差分。默认松弛系数0.25、单步上限
比例0.075；相对1600 MPa张拉上限等价为
约30 MPa的基准应力步长。每个施工组的背索/中跨索均为 A、B 分量保存独立步长记忆，n=24
共有96项。本分量绝对目标残差降至原来的70%以下且不换号时放大15%，残差变差或跨过零点时
减半，并限制在基准的1/32～2倍；一次完整回放即可更新全部记忆，不增加 FEM。索力候选
单独回放，只有位移平衡指标不增才接受。若全量候选被拒绝，则按与整体评分相同的归一化尺度
选出当前绝对目标残差最大的一个A/B索力分量，恢复其余索组，并额外进行至多一次完整FEM
回放；这个单分量候选仍须使整体位移平衡指标不增才会接受，未经验算的分组改动不会写入
检查点。验收后只更新该分量自己的步长记忆；其他索组不会因耦合的整组失败而被误缩步长。
这种逐分量回退按实际残差动态选择，能在整组耦合候选长期被拒绝时继续推进外侧B主索。
该反馈不构造影响矩阵，也不从全组
同步变化估计单索割线斜率，以免最终位移耦合导致外段过调；算法不要求单轮精确达到目标。

第二轮固定第一轮验收后的索力，只使用本组最终 `secondary_load` 有符号应力调整股数。
目标为500 MPa，按 `max(σ,0)` 反算各组股数后，以“本组目标根数差×0.125松弛系数×本组缓存”
作比例修正；默认同时受当前股数25%的相对上限和每循环25根的绝对安全上限控制。每个索组
的整数根数是独立变量，不再拟合四控制点 Bernstein 曲线，也不再施加由内向外非递减约束。
每个索组保存独立根数步长记忆：本组应力残差改善且不换号时放大15%，残差变差或跨过目标
时减半，并限制在基准的1/32～2倍。张拉上限所需的本组最小股数仍是硬下界。
最终应力小于0的索组进入强制分支：目标根数取当前根数的 `floor(2/3)`，绕过普通松弛、
独立缓存以及25根单轮变化上限，并在不低于A+B张拉容量下界和全局最小根数的前提下执行。
这种压应力强制候选完成FEM回放后即接受，即使全体500 MPa指标暂时变差；对应组的根数缓存
重置为中性值，下一循环继续根据新的最终状态判断。
根数候选独立回放，仅要求全体最终应力相对500 MPa的指标严格改善；位移变化在本轮只作
诊断，不再否决减根或增根。验收后的根数和受扰动位移进入同一循环的第三轮。第三轮固定
初始索力A、全部钢束根数和全部背索B，只按最终 `secondary_load` 的各主梁控制点位移修正
对应中跨索B。完整修复候选的唯一验收指标是 `max(abs(最终主梁 z))` 严格下降；桥塔RMS、
主梁RMS和应力指标都不再掩盖局部最大线形误差。完整候选失败时，恢复其他中跨索B，仅保留
当前绝对主梁位移最大位置的一组B并额外回放至多一次。这个隔离候选同样必须降低最大位移才
会写入检查点。修复轮继续复用各组独立B步长缓存：改善分量按现有规则自适应，经验算失败的
隔离分量单独减半。
拒绝根数候选不会回滚已验收的索力，也不会再因为整轮拒绝而同步减半所有索组缓存。通常
全新首循环为4次完整施工回放（基准、索力候选、根数候选、线形修复候选），同一进程后续循环
复用上轮最终阶段记录而新增3次；全量索力候选和全量线形候选失败时，各自至多额外增加1次
隔离候选回放。因此连续 C 轮通常为 `3*C+1` 次，最坏再增加至多 `2*C` 次。
跨进程续算首轮需重新回放检查点方案。该预算不随索组数量线性增加，但单次回放规模仍随
`n_seg` 增长。

每个完整循环后原子更新工程检查点、历史和 v3 物理设计。检查点保存已经完整验证的新股数、
A/B 张拉力、96项自适应索力步长和48项自适应根数步长，因而中断不会把未验证或已拒绝的
估算方案写成最佳设计。v13 可迁移读取 v4/v5/v6/v7/v8/v9/v10/v11/v12 数值状态；缺失的根数记忆初始化
为中性值，v4受旧耦合拒绝影响的全局小步长会重置为中性独立记忆。v8/v9中的独立索力和
根数缓存会原样保留；旧检查点中的预拱度和根数曲线设置被忽略，续算后直接使用最终零位移与
逐组独立根数语义；迁移v12后首个新循环会自动执行第三轮最终线形修复。

边界和工程目标必须与检查点一致。终端只刷新一个固定高度仪表板，24行施工组同时

只能作为线性调索初值，不能替代后续 `corotTruss`、索垂度和仅受拉非线性验算。
